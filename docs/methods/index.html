How to read this site

Methods

What is verbatim and what is ours

Each place page is built from the place's own typology document — a design-review by-law, an inventory or a characterisation study, named in the page header and sources. The five-column profile tables (“What the by-law says about this type”) are direct translations of those documents' tables, kept in the source's order and wording. The short descriptions (blurbs), the “Where it comes from” origin notes, and the phase essays are ours: researched, but interpretive. Style names attached to types are ours too, added so local vocabularies can be read in the shared language of architectural history; where a source names its own styles, the local name is kept in the type's style_label.

The canonical layer is interpretive

The canonical forms (data/canon/canonical_types.yaml) and styles (styles.yaml) are a controlled vocabulary we maintain, not something any municipality publishes. Assigning a local type to a canonical form flattens real ambiguity — a roof recorded as “two- or four-slope” becomes one value in the fixed fields, and the type's profile keeps the full wording. Treat cross-place links (“same form elsewhere”, “same style elsewhere”) as reading aids, not equivalence claims.

Nulls

Fields the source does not state are stored as null and render as an en dash “–”, never as an invented value. When a place's typology document is not a per-type table (style catalogues, model catalogues, inventories), each type record carries a profile_note saying how its fields were derived; it renders as a caption under the profile table.

Photographs

Photographs are reproduced from the source documents with per-photo credits (for Mount Royal: © Ville de Mont-Royal, By-law 1449, chapter II), for personal, non-commercial use. Where no photograph can be reused, records carry a placeholder until one is supplied; licences are recorded per photo in each type's photos list.

Data files

The build emits data.json and data.csv — every local type flattened with its place, phase, fixed fields, profile and styles — for reuse in GIS and notebooks. The YAML under data/ is the source of truth; everything in docs/ is generated by python build.py (Python 3.11, Jinja2, PyYAML).

Schema additions log

The Part 1 brief requires any key beyond the base schema to be recorded here. Additions so far:

  • phases[].summary_en — the short phase description shown in a place page's header timeline blocks (Part 1; carried over from the TMR site's phase blurbs).
  • types[].style_label — the verbatim display string for a card's “Style:” line, preserving the source wording (e.g. “Québec Revival (maison canadienne, néo-québécois)”) that a join of canonical style names would flatten (Part 1).
  • prose.md ## footer — an extra prose section for a place page's footer paragraphs (the by-law-intent note and vocabulary note on the TMR page), alongside the specified ## intro, ## phase:* and ## notes (Part 1).
  • types[].aliases — optional list of extra head-nouns for the “same word elsewhere” cross-links, per the brief; no record uses it yet.
  • types[].profile_fr — verbatim source French for a profile, keyed implantation / volumetrie / traitement_des_facades / ouvertures / materiaux (aligned to the English rows) plus sous_variantes, which renders as its own row; French shows in italics under each English list (Part 2a).
  • types[].source_generation — which generation of a place's typology documents a record was encoded from (the Plateau's 2004 Annexe D fiches versus the consolidated 2025 Annexe C); shown on type pages (Part 2a).
  • roof.form: flat-or-false-mansard — added enum value for the Plateau duplex with front setback, whose fiche treats the flat roof and the decorative false mansard as one type (Part 2a).
  • Phase colour keys p4/p5 — tints of the section colour at 70 % and 45 % for places with more than three phases (Part 2a).
  • types[].conservation / conservation_fr — the prescriptive sentences of conservation-guide fiches, separated from the descriptive profile and rendered as “Conservation guidance (fiche)” under the table (Part 3). Saint-Lambert's fiches organise their content as MATÉRIAUX / SAILLIES / OUVERTURES / VOLUMES ET AGRANDISSEMENTS / ORNEMENTATION; the mapping used is VOLUMES + SAILLIES → massing, ORNEMENTATION → articulation, OUVERTURES → openings, MATÉRIAUX → materials, with the fiche introduction feeding siting & landscape.
  • types[].models_observed — the model codes a catalogue place's address list records for a family, shown as a chip row (Part 4a).
  • types[].phase_confidence — verified or provisional, shown on the card, saying whether a record's phase rests on documentary evidence or on street position alone (Part 4a).
  • types[].model_addresses_csv — path to the parsed address list a record draws on; the build publishes it beside the data exports (Part 4a).
  • types[].display_order — explicit display order within a place, for catalogues whose source has no article or fiche numbering (Part 4a).
  • place.hero_photo — a place-level illustration with credit, for places where no photograph can honestly be attached to a single type; rendered under the intro (Part 4a).
  • Per-place model_families_summary.yaml — derived totals from an address list, rendered as the model-families table on the place page (Part 4a).
  • roof.form: null — permitted for records whose roof form is undocumented (Part 4a).
  • Per-place sectors.yaml (id, code, name_fr, value = exceptional|interesting|urban-ensemble, summary_en, streets, source) and types[].sectors — for places that classify territory rather than building types; the sectors render as a table on the place page and as linked chips on each type card (Part 5a).
  • place.grading — a per-building conservation grading system (Westmount's I*/I/II/III), rendered as a table under the place summary (Part 5a).
  • typology_document.format values sector-and-grading and sector-characterisation — for places whose published instrument grades buildings and zones territory instead of profiling types (Part 5a).
  • Phase colour key p6 — a 30 % tint of the planned-section colour, for places with six phases (Part 5a).
  • Enum values gabled-or-hipped, hipped-or-pyramidal, flat-or-low-slope (roof) and integrated-or-carport (garage) — Saint-Lambert fiches describe either/or forms as one type (Part 3).
  • sectors[].value: cited-site — added enum value for territory protected as a site patrimonial cité under the Loi sur le patrimoine culturel, rather than merely graded by an evaluation (Gatineau's Aylmer and Quartier-du-Moulin sites) (Part 6a).
  • sectors[].summary_fr — verbatim source French for a sector description, rendered in italics under the English, on the same principle as profile_fr (Part 6a).
  • sectors[].characteristics_fr — the RPCQ's éléments caractéristiques list for a cited site, kept as a bulleted French list because it is the legal description of what the citation protects (Part 6a).
  • sectors[].note — a per-sector caution, for the places where the source's own text is ambiguous, runs on into the next section, or is contradicted by another count (Part 6a).
  • types[].profile_fr.contexte, .repartition, .revetement — the Gatineau fiches head their sections « contexte / répartition géographique / volumétrie / ouvertures / revêtement / ornementation ». répartition maps onto siting and revêtement onto materials; contexte has no English column to sit under and renders as its own leading row, “Historical context (fiche)”, since it is the French behind the record's “Where it comes from” (Part 6a).
  • Cladding vocabulary wood-shiplap (planches à feuillure), wood-board-vertical, wood-piece-sur-piece, concrete-block and pressed-metal — materials the Gatineau fiches distinguish and the existing list had no term for; planches à feuillure in particular is named separately from clapboard on nine of the fourteen fiches (Part 6a).
  • Per-place inventory_summary.yaml and inventory.csv → place.inventory — a derived per-building inventory table with declared column headers, rendered under the place summary and published beside the data exports; Outremont's is the 1992 Bisson inventory as republished by the Ville de Montréal under CC BY 4.0 (Part 6a, generalised in Part 8a).
  • sectors[].code_eval2005 — a second code for the same sector. Westmount's By-law 1305 numbers its 39 heritage sectors 1–39 in Annexe I, while the Ville de Montréal's 2005 Évaluation numbers the same set 23.E.n / 23.I.n. The by-law's number is authoritative and the evaluation's is carried as a cross-reference; where the 2005 study did not retain a sector the field reads none rather than being guessed (Part 5a v2).
  • sectors[].value gains declared-site (protected by the government of Québec), review-jurisdiction (a permit-review boundary, not a heritage ranking — Québec City's CUCQ sectors) and unite-de-paysage (a landscape unit; Vieux-Terrebonne). sectors[].plan_de_conservation names the ministerial plan where one exists (Parts 7a, 8a).
  • place.sector_map — a rasterised map of a place's sector set, rendered above the sector table (Part 5a v2).
  • place.grading gains description_fr, intervention_fr and note per category and objectives_fr, criteria_fr and guideline_booklets at grading level — Westmount's By-law 1305 states what each category is and what may be done to it, and both belong on the page (Part 5a v2).
  • types[].tid, fiche_id, source_url, courant, quartiers, period_label, count_in_place and related_buildings — for the two places whose typology document is a live municipal catalogue rather than a PDF: Ville de Québec's thésaurus (node ids) and Ville de Lévis's styles architecturaux fiches (?idfiche=N). Each card links back to the page it was read from (Parts 7a, 8a).
  • types[].is_courant and types[].is_residential — a catalogue's parent categories and its non-residential entries are recorded from the source and appear in the data exports, but get no card and no page of their own. The place page lists them in a separate table saying why, so the source's list can be read whole (Parts 7a, 8a).
  • profile_fr keys with no English column of their own are now declared in one place — description and elements_caracteristiques (Ville de Québec), contexte (Gatineau), sous_variantes (the Plateau) — and each renders as its own row. Any profile_fr key that maps to neither a column nor a standalone row is a build error rather than silently dropped text. Lévis's plan, toiture and revetements headings map onto massing and materials (Parts 7a, 8a).
  • place.municipalities, place.parent_place, place.building_counts and place.built_fabric_statistics — for territories made of several municipalities, and for sources that publish several building counts measuring different things. The counts render as a table rather than as a single number on purpose: Île d'Orléans has four figures covering four different scopes, and Charlesbourg's 138 and ~200 count principal buildings and all buildings (Part 9a).
  • types[].is_group and types[].group_parent — a source may nest sub-variants under one type. The children keep their own records, pages and canonical memberships; on the place page they render inside the parent's card. The build refuses a group with no children, a child naming a parent that is not there, and a parent never marked as a group (Part 9a).
  • types[].page, types[].example_addresses and types[].municipalities — page anchors in a paginated source, the inventory's own printed example addresses, and which municipalities of a multi-municipality place a type occurs in (Part 9a).
  • sectors[].promoted_to_place and sectors[].value: parcel-system — the first for a sector that also has a place record of its own, rendered as a link rather than duplicated; the second for Charlesbourg's réserve, commune and ceinture, which are elements of a land division rather than heritage rankings (Part 9a).
  • Section rural-seigneurial, and roof form gabled-or-hipped-steep for the Île d'Orléans French-regime roof, which its inventory describes as two straight slopes or hipped, over 45° either way (Part 9a).
  • canonical.is_group and canonical.children — grouping at the canonical level, not just within one place. Montréal's plex family is one form to a Montrealer and seven distinct types to the boroughs that catalogue it, so the parent pools its children's members while each child keeps its own page. A group with no children, or a child that names a parent that is not there, is a build error (Part 10a).
  • canonical.alias_of — two ids for one form, kept because both are already cited. A record naming an alias attaches to the target form, and the alias page shows the target's members rather than an empty list, so an old link never becomes a dead end. plex-superposed-units now aliases plex-family, and wartime-housing-1940s aliases veterans-house-nha (Part 10a).
  • types[].variants — a numbered type that the source itself splits into lettered sub-cases (VSP's 1.1a / 1.1b) without giving each one a fiche of its own. Too thin for the is_group machinery, which expects children with records; rendered inside the parent card as a list (Part 10a).
  • place.borough_of — a place that is a borough of a larger city. The five Montréal boroughs get their own pages because they publish their own typologies, but on the home-page timeline they are grouped under one header rather than filed alphabetically among independent municipalities (Part 10a).
  • sectors[].value: archaeological-potential and style city-beautiful — the first for territory zoned for what may be buried under it rather than for what stands on it, the second for the idiom of Maisonneuve's civic building campaign (Part 10a).
  • Two new page kinds, /frameworks/ and /topics/, from data/canon/frameworks/*.yaml and data/canon/topics/*.yaml — described in the next section (Part 10a).
  • types[].topic_links — derived, never written by hand. A topic explains one building element across every place that has it, so the link is computed from canonical membership: every member of the plex family, its children and any alias pointing at it picks up the exterior-stair explainer. Interior-stair plexes are included deliberately, since they are the reason that page has to explain that the stair is not what defines a plex. Thirty-odd links across eight places, none of them repeated in a data file, and the build fails if a linked topic has no page (Part 10a).

Frameworks and topics

Two kinds of page that belong to no single place. A framework explains how one documentary series works — its code grammar, its categories, its method — so that every place drawing on it can point at one explanation instead of repeating it. A topic does the same for a single building element whose story is shared across places.

  • The Montréal framework — Évaluation du patrimoine urbain, and the art. 120 inventory — Framework — Ville de Montréal
  • L'escalier extérieur — the outside stair — Topic — one element, one explanation

The retro-fit, and a flag closed

Part 6 left a flag open: Outremont sector prefix unconfirmed — 16 or 17? The cahier's filename begins 17_, and that was the only reason to doubt the 16.E.n codes already encoded. Part 10 settled it by extracting the sector codes from the PDF text itself rather than trusting the filename, for all nine Montréal cahiers at once. Outremont is 16 — 17 appears nowhere inside as a sector prefix — and Westmount is 23, its 35 exceptional plus 4 interesting sectors matching the 39 already on the page. Both files were re-read and neither was changed: a confirmed negative, which is worth as much as a correction and is recorded here so the question is not reopened a third time. The reason the doubt was reasonable is that the two numbering sequences genuinely collide — file 27_ is Westmount (code 23) while code 27 is Mercier–Hochelaga-Maisonneuve (file 14), and file 22_ is Saint-Laurent (code 8) while code 22 is Le Sud-Ouest (file 12). The full mapping is on the Montréal framework page.

A sixth code letter, found three times over

The Évaluation's code grammar is usually given as E / I / N / U with AP as an archaeological overlay. Reading the cahiers themselves turned up a sixth: a bare A, used for a secteur d'intérêt archéologique one rank below à fort potentiel — AP marks ground needing protective measures, plain A marks ground needing study first. Three encodings found it independently, in three different volumes: 22.A.1 in Le Sud-Ouest (printed in a heading that reads « 22.AP.5, 22.AP.6 ET 22.A.1 »), 14.A.1 in Villeray–Saint-Michel–Parc-Extension, and 27.A.1–27.A.2 in Mercier–Hochelaga-Maisonneuve. No separate enum value was added, because Part 10a encodes E sectors only and no record depends on the distinction yet; the few A sectors that are recorded sit under archaeological-potential with the difference written into each note. It is logged here so that whoever enumerates the I / N / U / AP sectors in Part 10b adds the value rather than rediscovering the letter.

When an absorbed municipality becomes a place of its own

Three places here — Trois-Rivières, Lévis and Québec City — absorbed other municipalities in the 2002 mergers, and this site does not treat the absorbed ones consistently. It cannot: the sources do not. The rule adopted is promote a merged entity to its own place when a distinct typological source exists for it, and otherwise keep it as a sector. Charlesbourg is the case that meets the test — it has been inside Ville de Québec since 2002 and is still a sector of the Québec City page, but the ministerial plan de conservation publishes a five-type residential typology for it that the City's thésaurus does not, so it also has a place record, and the sector row links there instead of repeating it. Cap-de-la-Madeleine, Saint-Romuald and the rest have no such source and stay where they are. Stating the rule makes the inconsistency visible and deliberate rather than accidental.

Where Québec's own sources disagree about levels

The industrial vernacular is the clearest case. The Île d'Orléans inventory and the Ville de Lévis catalogue treat maison cubique, cottage vernaculaire américain and Boomtown as three top-level courants. The Charlesbourg plan de conservation and the Ville de Québec thésaurus nest all three under one parent, maison vernaculaire industrielle. Both readings are defensible and neither is ours to overrule, so the canonical layer carries both: the child forms hold the shapes, and a parent id holds the grouping. The same disagreement is why a canonical page can show more members than any one municipality would recognise.

Three words for the same level of abstraction

Ville de Québec says courant, Ville de Lévis says style, and Ville de Gatineau says type architectural — for objects at the same level. This site keeps its own split, canonical form for the shape of a building and style for the idiom it is dressed in, and records each place's native word in its typology document's format. Where one phrase names different objects in different places — maison de faubourg, plex, cottage — the glossary says so entry by entry, because that is exactly where a cross-place reading goes wrong.

When a form and a style point at the same buildings

Gatineau's three flat-roof fiches are the test case. They are filed here under the Boomtown style but not under the canonical form false-front Boomtown, and the fiches are the reason. A false front is a façade wall carried up past the roofline to hide it; all three Gatineau fiches mark the parapet as rare and give the frequent treatment as an ornamented cornice on the roof overhang, two of them with a porch under a triangular pediment — which a false front does not have. The wood fiche's own contexte makes the distinction for us: « Aux États-Unis, on associe souvent ce type au style Boomtown » — a style association, which is exactly where it is recorded. The rule this sets: a place joins a canonical form when its source describes the shape, and a style when its source describes the idiom. The two layers deliberately disagree about Gatineau, and the disagreement is the information.

How the sector evaluations chose their sectors

Four places on this site — Westmount, Hampstead, Outremont and the Plateau — are characterised by the Ville de Montréal's Évaluation du patrimoine urbain series rather than by a type catalogue, so it matters what that series was looking for. Sectors and buildings were selected on « leur capacité de témoigner d'un thème ou d'un événement historique; leur qualité architecturale (forme, usage, technologie constructive); leur participation à la qualité de la vie urbaine et du paysage » — their capacity to bear witness to a historical theme or event, their architectural quality of form, use and constructive technology, and their contribution to the quality of urban life and landscape. The notion of paysage urbain the series works with is drawn from Kevin Lynch. Sectors are graded on two levels, valeur patrimoniale exceptionnelle and valeur patrimoniale intéressante, and the codes on the sector tables are the evaluation's own.

Status

Part 1: scaffold, schema and the Town of Mount Royal migration (13 types, 3 phases). Part 2a: Le Plateau-Mont-Royal (12 types, 5 phases) encoded from the 2004 PIIA Annexe D fiches and the 2003 Patri-Arch typomorphological study; three duplex records are complete with verbatim French, the rest are partial or stubs pending the un-retrieved fiches, each carrying a profile_note saying exactly what is missing. Photographs for the Plateau are placeholders until the fiches are extracted. Part 3: Saint-Lambert — complete: all ten fiches of the Répertoire des courants architecturaux encoded with verbatim French, conservation guidance, and photographs extracted from the fiches themselves. Part 4a: Arvida — a model-catalogue place rather than a per-type-table one: ten records at the level of the model families (A, B, C, D, M, F, P–T, R, the grouped remainder, and Wartime Housing), each listing the model codes and streets parsed from the City's 2014 address list, with five-column profiles left empty except where a model is documented. Photographs from the City's Arvida site are all-rights-reserved and are not reproduced; a CC BY-SA street view stands as a place-level illustration. Part 5a: Westmount, Hampstead and Témiscaming — the garden-suburb and company-town family Mount Royal belongs to, and the first places that publish no type catalogue at all. Westmount grades every building (I*/I/II/III) and zones 39 heritage sectors; Hampstead and Témiscaming are characterised at sector or period level only. Their type records are reconstructions from sector fiches, National Historic Site character-defining elements and builder periods, with profile fields left empty wherever the sources are silent. Part 6a: Gatineau and Outremont — the two ends of the range. Gatineau is the first place after Mount Royal whose own documents are per-type tables: fourteen fiches published by the City in 2023, one per dominant residential form, each with descriptive columns and paired conservation sentences, encoded here with the source's French beside the English. Outremont is the opposite case — a borough that classifies buildings by dwelling count crossed with siting, and territory by landscape unit, and publishes no type table at all; its six records are drawn from the fourteen sector fiches of the 2005 evaluation and each says so, and its 1992 building inventory is republished as an open dataset and shown as a table. Gatineau's fiche photographs cannot be reproduced under the City's conditions of use, so freely-licensed photographs of the same types stand in their place and the fiche credits are kept on the placeholders. Part 5a v2: Westmount rebuilt on By-law 1305's own numbering — all 39 heritage sectors keyed to Annexe I's numbers 1–39 with the 2005 evaluation's codes carried alongside, and every sector named, coded twice and summarised; Hampstead's planner resolved to Leonard E. Schlemm with the Todd attribution rejected; Témiscaming's 2026 MRC inventory recorded as a negative finding, three retained properties, none residential. Parts 7a and 8a: Québec City, Vieux-Terrebonne, Trois-Rivières and Lévis. Québec City and Lévis are the first places whose typology document is a live municipal catalogue rather than a PDF, so both were crawled, parsed by a committed parser and encoded from the parser's output — no card on either page was written by hand, which is why none of them is empty. Terrebonne is the newest protection on the site, declared on 20 May 2026, and the thinnest set of type records: its declaration characterises four landscape units, not building types, and the four records say so. Trois-Rivières is a city legible as before and after one fire. Part 9a: Île d'Orléans and the Trait-Carré de Charlesbourg, the first places here whose organising unit is the farm lot rather than the street. The island's inventory grades all 659 of its buildings A–E, and that rating has had legal force since 2019, when asphalt shingle was permitted on C, D and E buildings outside the village sectors — 537 of the 659, and the only case on this site where a heritage rating directly determines a permitted material. Charlesbourg is a star-shaped village of 1665 whose forty trapezoidal lots are still legible under a 1950s suburb, and the one place whose typology nests sub-variants inside a parent type. Part 10a: five boroughs of Montréal — Le Sud-Ouest, Rosemont–La Petite-Patrie, Villeray–Saint-Michel–Parc-Extension, Mercier–Hochelaga-Maisonneuve and Verdun — together with the first framework page and the first topic page, which exist so that five boroughs can point at one explanation of the Évaluation's code grammar and one explanation of the exterior stair instead of repeating either five times. This is the part where the site stops treating a municipality as the unit of comparison: the five boroughs share a city, a code grammar and a housing stock, and disagree anyway. Rosemont treats the shoebox as one type and Villeray–Saint-Michel–Parc-Extension splits it in two, and the split has evidence behind it — that borough's own 2019 guide inventories 1 159 shoebox houses and finds 46.9 % of them built between 1950 and 1960. Le Sud-Ouest defines its plex family by dwelling count and puts interior-stair and exterior-stair types side by side in it, which is why the glossary entry for plex had to be rewritten. Every arrondissement code on these pages was read from inside its cahier rather than from the filename, because the two sequences collide outright — the file numbered 22 is Saint-Laurent, whose sectors are coded 8, while the arrondissement that owns code 22 is Le Sud-Ouest, published as file 12.
